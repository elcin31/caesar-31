## Воспроизведение

Из корня проекта, до изменения отслеживаемых файлов:

```sh
python scripts/verify_github_release.py --output research/recovery/2026-11-08/remote.json
python scripts/verify_recovery.py --output-dir research/recovery/2026-11-08 --epubcheck-jar /path/to/epubcheck-5.4.0/epubcheck.jar
```

Для следующего цикла использовать новый датированный каталог. Первая команда
сверяет актуальные HEAD и удалённый main, поэтому после последующего коммита
её отчёт будет относиться к другой контрольной точке. Вторая команда проверяет
сохранённый выпуск локально; существующие аудиты и verify_exports.py исполняются
на временной копии. Их результаты переносятся сюда, исходные dist/final/* не
перезаписываются. Пути dist/final внутри validation.json относятся к этой
временной структуре; новый журнал EPUBCheck сохранён рядом с данным README.
Без --epubcheck-jar валидатор явно запишет not_run для EPUBCheck.

Валидатор получен из официального выпуска W3C:
https://github.com/w3c/epubcheck/releases/tag/v5.4.0.
SHA-256 дистрибутива epubcheck-5.4.0.zip:
`33350c61038e71dfb3d45a76aed04bf5481e6d5500cb780f6e98db8bbd15a28c`;
сумма совпала с digest официального GitHub release asset. Хеш запущенного JAR
сохранён в local.json. ZIP/JAR валидатора в репозиторий не добавлялись.
